3. RESULTADOS DEL ENTORNO ACTUAL
--------------------------------

El contenedor `database-backend-1` ya estaba ejecutándose en el puerto 3000,
pero su red solo contiene el backend. Sus variables indican `DB_HOST=postgres`,
pero no existe un servicio PostgreSQL accesible con ese nombre.

- `GET http://127.0.0.1:3000/health`: falló.
- Error observado: `getaddrinfo ENOTFOUND postgres`.
- No se reinició ni se eliminó el contenedor existente para evitar afectar datos
  persistentes no controlados.
- Los contenedores ajenos observados (MySQL de otra aplicación y Jellyfin) no
  fueron modificados.

Este fallo pertenece al entorno Compose activo, no a la integración aislada que
fue levantada y validada correctamente.

4. HALLAZGOS Y RIESGOS
----------------------

- El directorio local antiguo `database/postgres-data` no debe reutilizarse como
  bind mount en Docker Desktop para Windows: PostgreSQL rechazó sus permisos.
- La configuración actual usa el volumen nombrado `postgres-data`, que resolvió
  el problema en la integración aislada.
- La instancia persistente antigua puede tener un esquema incompleto. Cambiar
  `schema.sql` no ejecuta migraciones sobre un volumen ya inicializado.
- La API activa usa `CORS_ORIGIN=*`; para un servidor real debe configurarse un
  origen concreto.
- El reporte no considera restauración sobre producción ni borrado de datos.

5. PRUEBAS PENDIENTES
---------------------

- Levantar el Compose del proyecto con un `database/.env` autorizado y validar
  el entorno operativo real.
- Decidir si los datos del directorio antiguo deben migrarse mediante un backup
  y restauración explícitos.
- Probar persistencia reiniciando el volumen nombrado, sin eliminarlo.
- Restaurar el dump en una base temporal y comprobar nuevamente la API contra
  esa base.
- Prueba visual con navegador y flujo completo mediante clicks.
- Pruebas funcionales completas de reservas, devoluciones, tickets,
  preferencias y permisos contra PostgreSQL activo.

6. CONCLUSION
-------------

El código, el frontend, Compose, el esquema limpio, el backend integrado y el
sistema de backups superaron las pruebas reproducibles disponibles. La
integración aislada Docker quedó validada de extremo a extremo.

El entorno actualmente activo sigue incompleto porque el backend apunta a
`postgres` sin tener un PostgreSQL accesible en su red. No se debe borrar ni
recrear la instancia persistente antigua sin conservar primero un backup válido
y contar con una decisión explícita sobre la migración de sus datos.
