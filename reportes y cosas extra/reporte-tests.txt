2. CORRECCION ENCONTRADA DURANTE LAS PRUEBAS
---------------------------------------------

validate_reservation_schedule de database/schema.sql.

Se corrigio la condicion SQL y luego PostgreSQL pudo inicializar correctamente:

- Extensiones.
- Tablas.
- Indices.
- Funciones.
- Triggers.
- Vista administrativa.
- Seis usuarios seed.
- Datos iniciales.

3. PROBLEMAS DEL ENTORNO EXISTENTE
----------------------------------

La instancia persistente actual tiene un volumen incompleto. Faltan tablas como
 tickets y loans.

PostgreSQL omite automaticamente schema.sql y seed.sql cuando el volumen ya
contiene datos. Por ese motivo, cambiar los scripts no reconstruye una base ya
inicializada.

Los contenedores existentes tambien presentan timeout entre servicios aunque
comparten la misma red Docker.

No se elimino ni reinicializo el volumen existente para evitar perdida de datos.

5. CONCLUSION
-------------

La pagina, el backend, el esquema limpio y el sistema de backup superaron las
pruebas automatizadas disponibles.

La principal limitacion actual esta en la instancia PostgreSQL persistente
existente, que tiene un esquema incompleto y problemas de conectividad entre
contenedores.

Antes de validar el entorno real completo se debe generar o conservar un backup
valido y reconstruir cuidadosamente el volumen incompleto, evitando borrar datos
sin una copia previa.
